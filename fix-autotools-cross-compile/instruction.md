## Autotools Cross-Compilation Toolchain Fix

Fix a broken autotools-based build system so that it successfully cross-compiles a "Hello World" C application for the ARM architecture (`arm-linux-gnueabihf`) from an x86_64 host.

### Setup

Run the setup script first to generate the broken project:

```bash
cd /app && python3 setup.py
```

This creates a project with intentionally broken autotools files (`configure.ac`, `Makefile.am`, `config.guess`, `config.sub`) and a simple C source file at `src/hello.c`.

### Requirements

1. **Cross-compilation toolchain**: Ensure the `gcc-arm-linux-gnueabihf` cross-compiler package is installed on the system.

2. **Fix `configure.ac`**: The file at `/app/configure.ac` must be corrected so that:
   - It includes the `AM_INIT_AUTOMAKE` macro (required by automake).
   - `AC_PROG_CC` is present so the compiler can be overridden via `--host`.
   - The file produces a working `configure` script when processed by `autoreconf`.

3. **Fix `Makefile.am`**: The file at `/app/Makefile.am` must be corrected so that:
   - It does not use the deprecated `INCLUDES` variable.
   - It does not hardcode host-specific include paths like `/usr/include`.
   - It correctly builds the `hello` binary from `src/hello.c`.

4. **Fix or replace `config.guess` and `config.sub`**: The stub scripts at `/app/config.guess` and `/app/config.sub` must be replaced with working versions (e.g., via `autoreconf -i` or by copying system copies).

5. **Generate the build system**: Run `autoreconf` (with appropriate flags) in `/app` to regenerate `configure`, `Makefile.in`, and all required auxiliary files.

6. **Configure for cross-compilation**: Run the generated `configure` script with the `--host=arm-linux-gnueabihf` flag to set up cross-compilation.

7. **Build**: Run `make` in `/app` to compile the project.

### Expected Output

After a successful build, the file `/app/hello` must exist and satisfy:

- `file /app/hello` output must contain `ARM` (case-insensitive), confirming it is an ARM binary.
- `file /app/hello` output must contain `ELF`, confirming it is a valid ELF executable.
- The binary must have been produced by the autotools build system (i.e., via `./configure --host=arm-linux-gnueabihf && make`), not by invoking the cross-compiler directly.

### Constraints

- Do not modify `src/hello.c`.
- The final `configure.ac` must contain `AM_INIT_AUTOMAKE`.
- The final `Makefile.am` must not contain the deprecated `INCLUDES` variable.
- A valid `Makefile` (generated by `configure`) must exist at `/app/Makefile` after the build.
