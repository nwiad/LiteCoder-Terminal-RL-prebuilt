## Dynamic Reverse Proxy with Health Checks

Set up an Nginx reverse proxy that routes requests to healthy backend servers with real-time health monitoring, load balancing, and a status dashboard.

### Technical Requirements

- **OS:** Linux (Debian/Ubuntu-based)
- **Proxy:** Nginx (installed and running)
- **Backend servers:** Simple HTTP servers (Python, Node.js, or any lightweight HTTP server)
- **Working directory:** /app

### Backend Servers

Start **3 backend HTTP servers** on the following ports:

| Server   | Port  |
|----------|-------|
| backend1 | 8081  |
| backend2 | 8082  |
| backend3 | 8083  |

Each backend server must respond to:
- `GET /` — return a JSON response: `{"server": "<server_name>", "status": "ok"}` with HTTP 200.
- `GET /health` — return HTTP 200 with body `{"status": "healthy"}` when the server is up.

Provide a script `/app/start_backends.sh` that starts all three backend servers in the background. Each server's PID must be written to `/app/backend<N>.pid` (e.g., `/app/backend1.pid`, `/app/backend2.pid`, `/app/backend3.pid`).

Provide a script `/app/stop_backends.sh` that stops all running backend servers using the PID files.

### Nginx Configuration

Place the main Nginx reverse proxy configuration at `/app/nginx.conf` (or `/app/nginx/nginx.conf`). The configuration must include:

1. **Upstream block** named `backend_pool` listing all three backend servers (127.0.0.1:8081, 127.0.0.1:8082, 127.0.0.1:8083).
2. **Reverse proxy** listening on port **8080** that forwards requests to the `backend_pool` upstream.
3. **Load balancing:** Default to round-robin. Include a commented-out `least_conn;` directive in the upstream block that can be enabled as an alternative algorithm.
4. **Health checks:** Configure `max_fails=2` and `fail_timeout=10s` on each upstream server entry so Nginx marks a backend as unavailable after 2 consecutive failures.
5. **Proxy headers:** Set `X-Real-IP`, `X-Forwarded-For`, and `Host` headers when proxying.

### Monitoring Dashboard

Provide a script `/app/health_check.sh` that:
1. Checks the `/health` endpoint of each backend server (ports 8081, 8082, 8083).
2. Writes results to `/app/health_status.json` in this exact format:

```json
{
  "timestamp": "<ISO 8601 timestamp>",
  "backends": [
    {"name": "backend1", "port": 8081, "status": "healthy", "response_time_ms": <number>},
    {"name": "backend2", "port": 8082, "status": "healthy", "response_time_ms": <number>},
    {"name": "backend3", "port": 8083, "status": "unhealthy", "response_time_ms": null}
  ],
  "healthy_count": <number>,
  "total_count": 3
}
```

- `status` must be `"healthy"` if the server responds HTTP 200, otherwise `"unhealthy"`.
- `response_time_ms` is the response time in milliseconds (integer), or `null` if unreachable.
- `healthy_count` is the number of backends with status `"healthy"`.

### Basic Authentication

Configure Nginx to serve a `/status` location on port **8080** that:
- Is protected with HTTP Basic Authentication.
- Uses credentials: username `admin`, password `monitor123`.
- The password file must be at `/app/.htpasswd`.
- When authenticated, proxies to or returns the content of `/app/health_status.json`.

### Stress Test Script

Provide `/app/stress_test.sh` that:
1. Sends **100 sequential HTTP requests** to `http://127.0.0.1:8080/`.
2. Writes a summary report to `/app/stress_test_report.json` with this format:

```json
{
  "total_requests": 100,
  "successful_requests": <number>,
  "failed_requests": <number>,
  "requests_per_backend": {
    "backend1": <number>,
    "backend2": <number>,
    "backend3": <number>
  },
  "average_response_time_ms": <number>
}
```

- Parse each response body to determine which backend handled the request (from the `server` field).
- `successful_requests` counts HTTP 200 responses. `failed_requests` counts everything else.
- `average_response_time_ms` is the mean response time across all successful requests (integer).

### Summary Report

Provide `/app/summary_report.md` documenting:
- The architecture (proxy port, backend ports, load balancing algorithm).
- How health checks work and failover behavior.
- How to start/stop the system.
- Results from the stress test (reference the stress test report).

### Expected File Structure

```
/app/
├── nginx.conf              # (or nginx/nginx.conf)
├── start_backends.sh
├── stop_backends.sh
├── health_check.sh
├── stress_test.sh
├── .htpasswd
├── health_status.json      # generated by health_check.sh
├── stress_test_report.json # generated by stress_test.sh
├── summary_report.md
├── backend1.pid            # generated by start_backends.sh
├── backend2.pid
└── backend3.pid
```

All `.sh` scripts must be executable (`chmod +x`).
