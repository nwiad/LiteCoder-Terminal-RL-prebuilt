## Encrypted Disk Recovery

Recover plaintext data from files encrypted with a flawed custom encryption tool that uses a predictable random number generator seed. You must analyze the encryption logic, identify the weakness, build a decryption tool, and produce the recovered files.

### Technical Requirements

- Language: Python 3.x
- Input directory: `/app/encrypted/` — contains encrypted files and the encryption tool
- Output file: `/app/output.json`

### Input Specification

The `/app/encrypted/` directory contains:

1. `encryptor.py` — the custom encryption tool source code. It encrypts files using XOR with a keystream generated by Python's `random` module. The seed is derived from a predictable value: the file's size in bytes at the time of encryption.
2. `file1.enc` — an encrypted text file (originally `file1.txt`)
3. `file2.enc` — an encrypted JSON file (originally `file2.json`)
4. `file3.enc` — an encrypted CSV file (originally `file3.csv`)
5. `manifest.json` — a JSON file listing metadata about each encrypted file:
   ```json
   {
     "files": [
       {
         "original_name": "file1.txt",
         "encrypted_name": "file1.enc",
         "original_size": 1024,
         "sha256_original": "abc123..."
       }
     ]
   }
   ```

The `encryptor.py` uses this pattern:
- Seeds `random.seed(original_file_size_in_bytes)`
- Generates a keystream of `random.randint(0, 255)` for each byte
- XORs each plaintext byte with the corresponding keystream byte

### Output Specification

Write a single JSON file to `/app/output.json` with this exact structure:

```json
{
  "analysis": {
    "encryption_method": "<string describing the encryption method>",
    "weakness": "<string describing the identified weakness>",
    "seed_strategy": "<string describing how the seed is derived>"
  },
  "recovered_files": [
    {
      "original_name": "file1.txt",
      "sha256": "<hex SHA-256 hash of the recovered plaintext>",
      "content_preview": "<first 100 characters of the recovered plaintext>"
    }
  ],
  "integrity_check": {
    "all_hashes_match": true,
    "details": [
      {
        "filename": "file1.txt",
        "expected_sha256": "<from manifest>",
        "actual_sha256": "<computed from recovered file>",
        "match": true
      }
    ]
  }
}
```

Additionally, write each recovered plaintext file to `/app/recovered/` using its original filename (e.g., `/app/recovered/file1.txt`).

### Requirements

1. Read and analyze `encryptor.py` to determine the encryption mechanism and seed derivation.
2. Parse `manifest.json` to obtain original file sizes and expected SHA-256 hashes.
3. For each `.enc` file, use the original file size from the manifest as the RNG seed, regenerate the keystream, and XOR-decrypt the ciphertext.
4. Write each recovered file to `/app/recovered/` with its original filename.
5. Compute the SHA-256 hash of each recovered file and compare it against the expected hash from the manifest.
6. The `analysis` section must contain non-empty strings for all three fields.
7. The `recovered_files` array must have one entry per encrypted file, ordered by `original_name` alphabetically.
8. `integrity_check.all_hashes_match` must be `true` only if every file's hash matches; otherwise `false`.
9. `content_preview` must contain the first 100 characters of the decoded plaintext (or the full content if shorter than 100 characters), with no trailing newline stripped.
